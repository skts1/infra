# Incident: Self-signed cert on www.sikrits.com (Aug 18, 2026)

## Timeline
- **Jul 8 2026** — Self-signed cert issued (predates Let's Encrypt setup)
- **Aug 18 2026 04:55 UTC** — Agent found `www.sikrits.com` returning self-signed cert warning
- **Aug 18 2026 00:57 GMT** — Let's Encrypt cert issued (CN=sikrits.com, SANs: sikrits.com + www.sikrits.com)
- **Sep 5 2026** — Browser cache still showing warning for some users (cert is actually valid)

## Root cause
Nginx `server_name` directive was updated to include `www.sikrits.com` AFTER
the cert was issued. The cert was never re-issued with the new SAN.

## Fix
- `certbot --expand -d sikrits.com -d www.sikrits.com`
- nginx `server_name sikrits.com www.sikrits.com;`
- `systemctl reload nginx`

## Prevention
1. **ssl-guardian.sh** cron (job 21e627b167cb) — every 15 min checks:
   - HTTPS returns 200
   - Cert issuer is Let's Encrypt (not self-signed)
   - SAN includes the hostname being checked
   - Cert not expiring within 21 days
2. **This repo** — if VPS ever rebuilds, restore-vps.sh re-issues cert with BOTH names from day 1
3. **Certbot expansion checklist** — every certbot invocation should include all server_names
